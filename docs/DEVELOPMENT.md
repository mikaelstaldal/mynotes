# MyNotes development guide

See [AGENTS.md](../AGENTS.md) for build prerequisites, architecture, and development conventions.

## Render kit

Native clients don't re-implement the MyNotes Markdown dialect. The browser
render pipeline is packaged as an embeddable **render kit** — a static page that
exposes `render(markdown)` / `setTheme(theme)` and does the rest (callouts, math,
diagrams, emoji, icons, wikilinks, sanitization) exactly as the web UI does. The
server serves it at `/render/`; `tools/dist-renderer.sh <outdir>` copies it into
a client for embedding in a web view. That page is also the one page the server
allows to be framed (`frame-ancestors 'self'`), so a sibling app deployed on the
same origin can embed it in an iframe and drive the same API.

## Stack

- **Backend:** Go, layered `handler → service → repository → SQLite`
  (`modernc.org/sqlite`, pure Go — no CGO).
- **API:** defined in `openapi.yaml`; Go server stubs generated by
  [ogen](https://ogen.dev/), TypeScript types by
  [openapi-typescript](https://github.com/openapi-ts/openapi-typescript).
- **Frontend:** [Preact](https://preactjs.com/) + TypeScript, compiled by `tsc`
  with no bundler; vendored runtime loaded via import maps.
- **Shared server plumbing:** auth, CSRF, gzip, security headers, and panic
  recovery from
  [`go-server-common`](https://github.com/mikaelstaldal/go-server-common).
- **Single-binary deploy:** the frontend is embedded with `//go:embed`.

## Layout

A summary of the directory tree:

```
main.go             # wiring, routing, middleware, graceful shutdown
openapi.yaml        # API contract — source of truth for both generators
internal/
  api/              # generated ogen stubs (gitignored)
  handler/          # api.Handler implementation + middleware
  service/          # validation, sanitization, business rules
  repository/       # SQLite schema, migrations, queries
  model/            # domain types
  sanitize/         # HTML sanitization
  demo/             # the demo seed content, and its export for the browser demo
web/ts/             # TypeScript frontend sources
web/ts/demo/        # the demo backend — a service worker standing in for the API
web/static/         # embedded assets (HTML/CSS/vendored preact/compiled JS)
web/static/render/  # the shared render kit embedded by native clients
tools/              # dist-renderer.sh — copies the render kit out for embedding
```
